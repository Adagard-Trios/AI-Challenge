# Slim runtime deps for the deployed backend (Render web service).
#
# WHY THIS FILE EXISTS
# --------------------
# requirements.txt is the full local-dev set: it also installs TensorFlow,
# PyTorch and the training stack so main.py can load the four ML models
# *in-process*. That set measures 3.12 GB installed and OOMs a 512 MB instance.
#
# In deployment the models run as their own Render services and the backend
# reaches them over HTTP (see src/model_gateway.py), so none of that is needed.
#
# THE ACCIDENTAL 3 GB
# -------------------
# The backend has no module-level import of torch/tensorflow anywhere. But
# langchain_groq.chat_models imports `transformers` *if it happens to be
# installed*, and transformers then imports torch. Verified: blocking both
# modules still lets `from langchain_groq import ChatGroq` and ChatGroq(...)
# work fine — it is a soft dependency. Simply not installing them removes the
# import, and with it the bulk of resident memory.
#
# ChromaDB is unaffected: chromadb_store.py passes CHROMADB_EMBEDDING_MODEL as
# collection *metadata* only, so Chroma uses its bundled ONNX embedder rather
# than sentence-transformers.
#
# CONSEQUENCE
# -----------
# Three of the four models cannot run in-process with this set: weather and
# currency are Keras .h5 and need TensorFlow, and stock needs it too. They
# require their <MODEL>_SERVICE_URL to be set, or they return the gateway's
# unavailable response — and the dashboard says so rather than showing a card
# that looks broken.
#
# Anomaly detection is the exception and DOES run here; see scikit-learn below.
#
# Use requirements.txt for local development where in-process models are wanted.

# NOTE: playwright is deliberately absent.
#
# The original reason was "collection runs in the user's connector". The
# connector has since been merged into the backend, so that sentence is no
# longer true -- but omitting playwright still is, for reasons that do not
# depend on it:
#
#   - ~400 MB of image and Chromium's 100-300 MB resident footprint, against a
#     512 MB instance with a ~210 MB base.
#   - Connecting an account cannot work on a server at all. browser_login.py
#     launches with headless=False so a human can complete 2FA, and sessions
#     are encrypted to the OS keyring of the machine that created them. A
#     container has no display and no such keyring.
#
# So social collection runs on the user's own machine (HOSTING.md), and the
# deployed API serves everything else. utils.py guards the import
# (PLAYWRIGHT_AVAILABLE), so the server boots fine and browser-backed tools
# report themselves unavailable rather than crashing.
#
# Both session-free scrapers that needed a browser (rivernet, weather nowcast)
# have been rewritten as plain HTTP calls. Nothing here needs a browser.

# Anomaly detection runs IN THIS CONTAINER. ~35 MB installed, well within the
# 512 MB budget, and it is the one ML model that fits.
#
# The catch was never sklearn -- it was the embeddings. The committed 768-dim
# isolation forests take distilBERT vectors from transformers + torch, which
# are not installed here, and their vectorizer returns np.zeros(768) instead of
# failing. Measured: every event then scored +0.012138 and was flagged
# anomalous, while /api/anomalies reported "ml_active".
#
# So the production model is re-fitted on 384-dim all-MiniLM-L6-v2 ONNX
# embeddings, which chromadb below already ships (no torch). See
# src/embeddings.py and scripts/train_anomaly_minilm.py.
scikit-learn
